# キーワード(タグ)一覧

現行実装([game-rules-minimum.md](game-rules-minimum.md))のキーワード(カードの
`Tags`フィールドで持たせる能力語)を、色ごとに一本化した一覧。以前は
game-rules-minimum.md・next-ruleset-cards-v1.mdの複数箇所に似た説明が分散して
いたため、ここを唯一の定義元にする。各色の由来・世界観は
[カードゲーム 世界観・フレーバー設定.md](<カードゲーム 世界観・フレーバー設定.md>)、
カード個別の一覧は[next-ruleset-cards-v1.md](next-ruleset-cards-v1.md)を参照。

## 一覧

| キーワード | 色 | ルール上の効果 | 世界観上の意味 | 実装上のタグ文字列 |
|---|---|---|---|---|
| 疾駆(Haste) | 赤 | このユニット自身、登場したターンでも攻撃できる | 決闘は「先に抜く」ことがすべて。誰よりも速く刃を抜き、赤熱させる | `"Haste"` |
| 分身(Clone) | 緑 | 発動条件(カードごとに異なる。下記「分身の発動条件」参照)を満たすと、このユニットの素の状態(バフ・キーワード無し)のコピーをトークンとして1体出す。このユニット1体につき生涯で1回だけ発動し、登場時効果はコピーが場に出たときにも発動する | 使徒が教えを広め、巡礼の列に仲間が加わっていく。紫の「変貌」が質の変化なら、緑の「分身」は量の増加 | `"Clone"` |
| 庇護(Guard) | 紫に多い(専用ではない) | このユニットが場にいる間、相手の攻撃は必ずこのユニットへ向く | 変貌が完成するまでの巡礼者を、まだ姿を変えていない仲間の護衛が守る | `"Guard"` |
| 封印(Seal) | 青 | 対象ユニットを場から完全に除去する(死亡時効果は発動せず、捨て札にも送られない) | 書物に記された術で、頁ごと閉じ込めて二度と読み返せなくする | `"Seal"` |
| 変貌(Transform) | 紫 | 条件を満たすと別のユニットに変わる。場を離れると変貌前のカードに戻る。変貌前に受けていたバフ/デバフや被ダメージは、変貌先の基本ステータスに差分として引き継がれる | 装いを重ねすぎた者が、その象徴そのものへ成り代わる | `"Transform"` |
| 先物(Discount) | 橙 | このユニットが登場したとき、コインを1増やす(以前は「次の購入1回だけコストが割引される」だったが、「バニラを無くしたい」というフィードバックでO02に先物を追加する際、キーワード自体を単純なコイン付与に変更した) | 商人はまだ手にしていない積荷にも値を付ける | `"Discount"` |

無色カードはこの6つのいずれも持たない(game-rules-minimum.md「色ガイド」参照)。

### 分身の発動条件(CGCloneConditionId)

分身の発動条件はカードごとに異なる。現行実装の一覧は
[next-ruleset-cards-v1.md](next-ruleset-cards-v1.md)「緑」参照。

| 条件 | 内容 |
|---|---|
| AllyUnitCountAtLeast | 場の味方Unit数(自分自身を含む)が指定数以上になった瞬間 |
| SurvivedAttack | このユニットが(防御側として)攻撃を受けて生き残ったとき |
| AttackedAndSurvived | このユニットが(攻撃側として)攻撃して生き残ったとき |
| LeaderHealed | 味方リーダーが回復したとき |
| LeaderHpAtMost | 自分のリーダーの体力が指定値以下になったとき |

### 庇護は紫に多いが専用ではない

庇護は「変貌が完了した後の強化」ではなく、「変貌が完了するまでの投資(変貌前の
軽いUnit)を守るための護衛」という位置づけで、紫の非変貌Unit(P05/P11/P14)に
持たせている。変貌先カード「P12T 万物の頂点」は別枠の例外として従来通り
庇護を保持する。ただし庇護は紫専用のキーワードではなく、他色のカードに
例外的に付けても構わない(現に緑のG07猛る大鹿にも1枚だけ持たせている)。
「紫に多いだけ」という位置づけで、キーワードと色の対応は厳密な1対1ではない。

## キーワードとパッシブは別物

上表の5つは**個々のカードに付く能力語**(`Tags`)。これとは別に、色ごとに
「デッキの17枚以上をその色で占めると発動するパッシブ」があり、報酬は5色とも
共通で「コイン+1(1ターン1回)」に統一されている(条件だけが色ごとに異なる)。
パッシブの条件・キーワードとの対応・実測バランスはgame-rules-minimum.md
「色ガイド」の色ごとの表を参照。

## 新しいキーワードを追加する手順

[architecture.md](architecture.md)「カードデータモデル」内の「新しいキーワード
(タグ)を追加する手順」を参照(`Tags`に文字列を1つ足し、判定が必要な箇所に
`Def.HasTag(...)`の分岐を足すだけで済む設計)。
