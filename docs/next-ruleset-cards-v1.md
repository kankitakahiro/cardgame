# 次期ルール カードリスト v1(5色、計76種。紫のみ16種、他4色は15種ずつ)

現行実装([game-rules-minimum.md](game-rules-minimum.md))のカードプール一覧。
しきい値(17/25)・封印の強さ・変貌の複雑さなどの論点を、実際にカードがある
状態で検証しながら育ててきたリスト。**バランス数値は各カードの「ナーフ」列に
経緯を記録済み。**

## このドキュメントの前提

- デッキ25枚、同名カード3枚まで、しきい値17枚でパッシブ発動
- マナ上限10、共通マーケット6枠(購入者の山札トップで補充)
- 「想定強さ」は`initial-cards-v0.1.md`のようなManaRatio計算ではなく、キーワード
  (定義は[keywords.md](keywords.md)参照)を含む効果を経験則で見た定性評価。
  新キーワードの価値がまだ数値化できていないため(要検討: 各キーワードの点数化)。
- 各カードのフレーバーテキスト例・色ごとの世界観は
  [カードゲーム 世界観・フレーバー設定.md](<カードゲーム 世界観・フレーバー設定.md>)
  を参照(このドキュメントのカード名・効果とは別に検討されたもので、現状は
  1対1で対応していない)。
- カードIDは色頭文字+連番(赤R/橙O/緑G/青B/紫P)。実装時のCardIdとは別体系。
- デッキ構築で選べるカードプールは、以下の5色76種(紫のみ16種、他4色は
  15種ずつ)に加えて「無色」24種(`initial-cards-v0.1.md`、旧ルールからの
  流用)を合わせた計100種。無色はどの色にも属さず、しきい値のカウント対象外
  (`docs/game-rules-minimum.md`「色ガイド」参照)。

## 緑(物量/分身/回復)— 分身

パッシブ: 自分のターン開始時、場にUnitが3体以上いればコイン+1(1ターン1回。
docs/game-rules-minimum.md「色ガイド」参照)。

以前は庇護(Guard)が緑の識別キーワードだったが、庇護は紫の護衛カードへ移し
(docs/keywords.md「庇護は紫の護衛カードだけが持つ」参照)、代わりに緑固有の
新キーワード「分身」を導入した。分身は発動条件を満たすと素の状態(バフ・
キーワード無し)のコピーをトークンとして1体出す、このユニット1体につき生涯で
1回だけの能力(docs/keywords.md「分身(Clone)」参照)。以前庇護を持っていた
7枚(G01/G03/G06/G09/G12/G13/G15)がそのまま分身持ちになった。発動条件が
緩くなった分、素のステータスと登場時効果の値を全体的に下げてある
(「登場時効果を持つカードに分身を付けると効果量が実質2倍になる」という
バランス上の注意点への対応。特にG06/G15は登場時ヒール量も削っている)。

500戦シミュレーションで緑が59.9%(個別カードも15種中1枚も50%を下回らない)
という突出した結果になったため、分身持ち7種のステータスをもう1段階下げた
ところ、今度は40.4%(15種全てが50%未満)まで下がりすぎた。そのため
この1段階分は巻き戻し、下表は「庇護→分身への変更時」の1段階ナーフのみが
乗った状態になっている。また、トークン生成スペルのうち「大群の号令」(G11)は
「トークンを出すスペルが強すぎる」というフィードバックを受けて削除し、
代わりに自分の場のUnit数を参照する除去スペル「群れの猛攻」を新設した
(3コスト、敵Unit1体に自分の場のUnit数と同じダメージ。トークンは増やさず、
物量を攻撃力に変換する役割。ただし単体では31.2%と弱く、今後さらなる調整が
必要)。

追加前32.1%とほぼ同水準)は動かず、紫の弱さはスピードの問題ではなく
基礎性能・対除去耐性の問題だと裏付ける結果になった(next-ruleset-
simulation-v1.md「第19回」)。この結果を受けて、紫の全Unit(P01/P03/
P05/P06/P08/P09/P11/P12/P14/P15/P16、変貌前・単体問わず)のHPを一律+1し、
変貌先カード(P01T〜P15T)のステータスも一律+1/+1する形で色全体を
底上げした(第20回)。5000戦で紫32.1%→**55.3%**まで改善し、他色も
紫を除き46.7〜50.2%の狭いレンジに収まっている。

その後、「庇護を紫のキーワードに変更してほしい(変貌後の強化ではなく、
変貌前の投資を守る護衛カードのイメージ)」というフィードバックを受けて、
非変貌のUnitカード(P05/P11/P14)に庇護を追加した。護衛が変貌前のP01/P03等を
守れるようになった分、「紫のステータスを全体的に下げてほしい」という
追加フィードバックに従い、第20回で乗せた+1のうちHP側を全Unit(P01/P03/
P05/P06/P08/P09/P11/P12/P14/P15/P16、変貌先P01T〜P15Tも含む)から一律で
巻き戻した。P15Tだけは元々HP4と紙耐久な設計のため据え置きにしている
(下記「変貌先カード」参照)。この巻き戻しの効果はシミュレーションでの
再測定がまだ済んでいない。

### 変貌先カード(P01T〜P15T)

いずれも紫(変貌元と同色)。マーケットには並ばず、購入・手札からのプレイも

## バランス調整について

各カードの「効果」「想定強さ」列は初出時点の設計意図のみを載せ、実際に
加えたナーフ/バフの概要は同じ行の「ナーフ」列にまとめている(変更が無い
行は「―」)。調整は3000戦単位の自己対戦シミュレーションで勝率を計測しながら
反復した(詳細な回次ごとのログは反映済みのため削除済み)。カードの現在の数値は
`CGCardDatabase.cpp`を正データとすること(このドキュメントの数値・ナーフ欄は
反映漏れが生じ得るため、実装との食い違いに気付いた場合はコード側を優先し、
必要に応じてこのドキュメントも合わせて直すこと)。

## サンプルデッキ(色ごとの基本デッキ)

各色15種類のうち、キーワード(疾駆/先物/庇護/封印/変貌)を持つか軸となる
効果を持つ低〜中コストのカード5種類を3枚ずつ、残り10種類を1枚ずつ採用した
25枚デッキ(5×3+10×1=25)を1色につき1つ用意している。全て単色なので
25/25でしきい値(17/25)を余裕を持って超え、パッシブは確実に発動する。
`UCGCardDatabase::GetBasicColorDeckCardIds(Color)`としてコードにも実装済みで、
対戦AI(Side1)がロビーの「対戦相手デッキ」画面で選ばれた色を使う(未選択なら
この5色からランダムに1つを選ぶ。`ACGGameMode::InitializeMatch()`、
`UCGGameInstance::SelectedAIOpponentColor`参照)ほか、3000戦シミュレーションの
母集団にも使っている。あくまで「色の個性を体感する」ための基本形であり、バランス
調整済みの完成デッキではない。カードの現在の数値はこの節ではなく上記の
カード一覧(またはコード)を参照すること。

| 色 | ×3で採用 | ×1で採用(残り10種) |
|---|---|---|
| 赤(速攻/バーン) | R01, R02, R04, R07, R10 | R03, R05, R06, R08, R09, R11, R12, R13, R14, R15 |
| 橙(購入加速) | O03, O06, O08, O09, O14 | O01, O02, O04, O05, O07, O10, O11, O12, O13, O15 |
| 緑(物量/守護) | G01, G03, G05, G06, G09 | G02, G04, G07, G08, G10, G11, G12, G13, G14, G15 |
| 青(除去/追放) | B01, B03, B07, B08, B11 | B02, B04, B05, B06, B09, B10, B12, B13, B14, B15 |
| 紫(強化/変容) | P01, P02, P03, P05, P08 | P04, P06, P07, P09, P10, P12, P13, P14, P15, P16 |

橙は当初`O01,O03,O06,O08,O11`だったが、3000戦シミュレーションで最弱色
(44.3%)と判明したため上記の構成に変更し57.7%まで改善した。赤もR08を
試験的に3枚採用してみたが悪化したため元の構成に差し戻している。紫はP16追加に
伴い×1採用のP11(予見の魔導師)をP16に入れ替えているが、勝率(31.9%)は
ほぼ変わらなかった(紫の弱さ自体はこの後のステータス一律強化で改善した。
下記カード一覧のP01〜P16のナーフ欄参照)。

今後の見直しポイント: 現状いずれの色も5〜6コスト帯が薄め(×1のみ)。実戦で
高コスト帯が弱すぎると分かれば、該当色の×1カードの一部を×2〜×3に増やす
調整があり得る。また人間側(デッキ未構築時のフォールバック)は引き続き
`GetStarterDeckCardIds()`(複数色混在)のままにしている。

## 実装メモ(現行アーキテクチャとの接続、着手時用)

- `FCGCardDef`に`Color`(enum)、`Keyword`群(疾駆/庇護/封印/変貌/先物を
  タグとして。既存の`Tags`(カンマ区切り文字列)をそのまま拡張できる)を追加。
- 変貌は「変貌後カードのCardId + 変貌条件の判定関数」をカード定義に持たせる形が
  既存の`EffectId`ディスパッチ方式と馴染みやすい。
- マーケットの所有権追跡(このリストの前提となる、購入者の山札トップで補充する
  仕組み)は`ACGGameState::MarketCardIds`を`TArray<FName>`から
  `TArray<FCGMarketSlot>`(CardId + 由来SideIndex)へ拡張する形になりそう。
